  - **HARD 1 — the "image in use is never removed" protection is inert, and that is the whole safety of this script.** `deploy/bin/makam-prune-images:126-128` compares a string built from `docker inspect {{.Image}}`, which is `sha256:<64 hex>`, against `$id` from `docker image ls {{.ID}}`, which is the **12-character short form**. Verified by adding `docker image prune -a` to each of those four files in turn — all four now fail the build. The "exempt exactly one file" test compared a constant with itself, and hid the fact that a prune *inside* the fixture file went unflagged; it is replaced by two behavioural ones: the rule is shown flagging the fixture file, so the exemption is visible rather than a hiding place, and the exemption list is checked to hold one path that exists.

  - The runbook called the prune `makam-deploy` "step 9"; the script's own header and its call site both say 8. The runbook now calls it the script's last step, step 8, instead of picking a number that can drift again.

## Acceptance criteria

- [x] Every deploy (the host's `makam-deploy`) keeps at most the last 3 makam image versions per environment on the host (the running one and the previous one always among them) and removes only `ghcr.io/andrianm28/makam` images; other projects' images are never touched.
- [x] A monthly GitHub Actions workflow deletes ghcr `sha-*` versions older than 30 days, except any currently deployed to staging or production and any `v*` release tag.
- [x] Dev work: AGENTS.md tells builder agents to remove their own compose stack, dev image and `node_modules` when a ticket is merged, and names the per-worktree image tag pattern so the cleanup is exact.
- [x] A disk check (on the existing health timer or GlitchTip/uptime alarm) warns when the root disk passes 85%.
