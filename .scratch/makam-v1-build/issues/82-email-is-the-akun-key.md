# Email becomes the Akun key; the WhatsApp channel is removed

Status: ready-for-agent
Blocked by: —
Spec: Domain modules > 1. Identity & Access; Adapter ports (WhatsAppSender removed, EmailSender); 15. Notifications (Kode Masuk exception, channels); 17. Pengaturan Operator (CS WhatsApp for `wa.me` only); Out of Scope; ADR 0004 (supersedes ADR 0003); `CONTEXT.md` (Akun, Kode Masuk, Email Terverifikasi, Undangan Staf, Pemulihan Akun, Peringatan Staf); stories 21, 26, 27, 98, 167, 170, 189, 190, 191, 193

## What to build

Apply ADR 0004 to the identity module and everything built on the WhatsApp channel. v1 sends nothing through WhatsApp: the WhatsApp Kode Masuk, the `WhatsAppSender` port, its in-memory fake and every reference to them go away. An **Akun is keyed by its Email Terverifikasi** and is created or logged into by a Kode Masuk sent to that email, at Kirim in a wizard or on Masuk. The phone number stays on the Akun as a required contact that is never verified and never logs anyone in. Undangan Staf are addressed to an email. Pindah Nomor becomes **Pemulihan Akun**: Admin Platform moves an Akun to a new Email Terverifikasi after a KTP check. A family without email sees "Tidak punya email? Minta bantuan CS", which opens a `wa.me` link to the CS WhatsApp number from Pengaturan Operator and shows the CS phone.

This ticket changes behaviour that is already merged (tickets 08, 09, 21, 63, 67, 69, 70). The code rules stay the same. Only the channel and the key change.

## Acceptance criteria

- [x] **Identity schema, expand/contract** (`-- contract:` on the destructive step, per ADR 0002): the Akun is keyed by a unique, case-insensitive Email Terverifikasi, and its phone number becomes a required, unverified contact (still +62, normalised by `normalisePhoneNumber`). An existing Akun that has an Email Terverifikasi keeps working with its roles, orders and Entri Audit. An Akun without one cannot log in until an Admin Platform does a Pemulihan Akun. The migration never invents an email. Its effect on existing rows is written in the migration and in Comments.
- [x] **Kode Masuk by email only**: `requestKodeMasuk(email)` / `verifyKodeMasuk(email, code)` (or the existing email-login functions, renamed) on Masuk and at Kirim. They log into the Akun of that email, or create the Akun when the email has none. The Akun is created only when the code is entered, and entering it proves the email. The limits stay as before: 6 digits, 10 min expiry, the 5th wrong code burns it, resend after 60 s, at most 5 per rolling hour per email and per IP, and the per-Akun lockout after 10 wrong codes in 60 min. The code is sent directly through EmailSender: no message-log entry, no retry, no Antrean row, and "gagal kirim" is not counted against the limits. The reply is the same for every email.
- [x] **Removed**: the WhatsApp Kode Masuk (`requestOtp` / `verifyOtp` by number), the "Kirim lewat email" fallback and `tanpa_kode_whatsapp`, the WhatsApp channel in `identity_otp_request`, the `WhatsAppSender` port (`src/ports`), its memory fake (`src/adapters/memory`), its slot in `src/composition/adapters.ts`, the dev route `/api/dev/whatsapp-outbox`, the e2e helper `e2e/support/whatsapp-outbox.ts`, and every seed, CLI and test reference to them. Template #43 `staf_undangan` is retired. `grep -ri whatsapp src e2e` finds only the CS `wa.me` link and Pengaturan Operator's `csWhatsApp`.
- [x] **Peringatan Staf**: `sendStaffAlert` (ticket 21) sends web push to every Perangkat Push and an email to the Akun Staf's Email Terverifikasi instead of WhatsApp, and `createNotifications` no longer takes `whatsapp`.
- [x] **Masuk and the Kode Masuk component** (`OtpVerification`, renamed if it helps) show only email: one email field, then the code. There is no number field, no "Masuk dengan email" switch and no fallback slot. The copy uses `CONTEXT.md` words (Kode Masuk, Email Terverifikasi).
- [x] **"Tidak punya email? Minta bantuan CS"** appears on Masuk and in the Kode Masuk component used at Kirim. It is a `wa.me` link to `csWhatsApp` with the reply hours, and it also shows the CS phone. While Pengaturan Operator is empty, it names no number.
- [x] **Undangan Staf by email**: the invite form takes an email (required) and a phone number (contact). The invite is sent through EmailSender and accepted, audited as `staf.peran_diberikan`, when the Akun whose Email Terverifikasi is that email next logs in with a Kode Masuk. That Kode Masuk creates the Akun if needed. Re-inviting a Dinonaktifkan Akun still reactivates it.
- [x] **Pemulihan Akun** replaces Pindah Nomor, in the domain function, the Admin Platform page, the menu and the audit action label. It needs "KTP sudah dicek", the KTP file (same type and size checks, FileStore), a reason and a new email that is not another Akun's key. It moves the Akun to that email as its Email Terverifikasi, ends its sessions and keeps everything recorded on the Akun. It is audited, and it refuses the acting Admin Platform's own Akun. The storage refusal copy reads "... Email belum dipindah." with no ticket number.
- [x] **Akun Saya**: the phone number can be edited, with validation only (+62, normalised). The email is changed only through Verifikasi email and cannot be removed. "Simpan tanpa verifikasi" and "Hapus" for the email are gone.
- [x] **CLIs and runbook**: `seed:admin` takes `--email` (seeded as the Email Terverifikasi) and `--phone` (contact). `verify-email` is either retired or keyed by email, decided and recorded in Comments. `reset-totp` takes the email. `docs/ops/runbook.md` is updated and no longer says "until ticket 62". `AGENTS.md` loses the WhatsAppSender port and the WhatsApp OTP exception wording, and names the email Kode Masuk instead.
- [x] **Tests at the identity module seam**, named in glossary terms, for example: "a Kode Masuk to an unknown email creates the Akun only when entered"; "a Kode Masuk logs into the Akun of that Email Terverifikasi"; "the Kode Masuk limits are counted per email and per IP"; "the phone number never logs anyone in"; "an Undangan Staf is accepted by the Akun with that Email Terverifikasi"; "Pemulihan Akun moves an Akun to a new Email Terverifikasi after a KTP check, audited"; "Verifikasi email refuses an email that is another Akun's key"; "an Admin Platform still passes TOTP after a Kode Masuk"; "a Peringatan Staf reaches every Perangkat Push and the email".
- [ ] **e2e updated**: `masuk.spec.ts` and `staf.spec.ts` (and the helpers) log in through the fake email outbox. The e2e Admin Platform is seeded by email. Each spec file stays under 10 s once the stack is warm.
- [x] lint, typecheck, `npm test`, `npm run build` and `npm run build:worker` are clean. A migrate upgrade test runs on a copy of a database with existing Akun.
